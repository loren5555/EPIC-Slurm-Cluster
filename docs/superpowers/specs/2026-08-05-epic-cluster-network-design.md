# EPIC 集群双网口与出口设计

日期：2026-08-05
状态：用户已确认架构，待实施

## 1. 目标与边界

新控制节点 `epic-cluster-controller-01` 替代旧方案中的 Windows 出口主机。校园网只直接服务控制节点；所有计算节点位于固定的实验室局域网，通过控制节点访问互联网。

本方案只建设一个内部 IPv4 子网，不配置 VLAN、多出口、链路聚合、动态路由或高可用网关。控制节点其余网口保持未配置状态。

## 2. 物理拓扑

```text
校园网
  │
  │ DHCP / 校园网认证
  │
epic-cluster-controller-01
  ├── 校园网口：获取校园网地址和系统唯一默认路由
  └── 集群网口：192.168.5.251/24
          │
          └── 企业路由器 LAN 口
                  ├── 管理地址：192.168.5.1/24
                  ├── WAN 口：不连接
                  ├── DHCP 与固定租约管理
                  └── 另一个 LAN 口
                          │
                        交换机
                          │
                     所有服务器
```

路由器和交换机处于同一个二层广播域。交换机保持默认二层配置，不配置 VLAN 或三层路由；路由器不执行互联网出口 NAT。

## 3. 组件职责

### 控制节点

- 校园网口通过现有方式获取校园网地址、DNS 和默认路由。
- 集群网口固定为 `192.168.5.251/24`，不配置第二条默认路由。
- 开启 IPv4 forwarding。
- 使用 nftables 对 `192.168.5.0/24` 到校园网口的流量执行一次源 NAT（masquerade）。
- 允许内网主动访问校园网，并允许相关返回流量；不把校园网入站连接转发到计算节点。
- Slurm、MUNGE、NFS 和节点管理均使用内部地址。

### 企业路由器

- 使用 LAN 口连接控制节点和交换机，WAN 口保持断开。
- 提供内部设备列表、DHCP 和固定租约管理。
- DHCP 默认网关优先下发 `192.168.5.251`，DNS 下发 `223.5.5.5` 和 `119.29.29.29`。
- 如果设备无法自定义 DHCP 默认网关，则服务器使用静态网络配置；路由器只为临时设备提供 DHCP。

### 交换机

- 仅扩展物理端口。
- 所有服务器端口保持在默认的同一 VLAN。
- 如果管理地址可配置，使用 `192.168.5.2/24`；管理界面不可用不影响集群通信。

### 服务器

- 正式服务器使用固定地址，不依赖动态租约维持 Slurm 通信。
- 默认网关为 `192.168.5.251`。
- 子网掩码为 `/24`。
- 不配置校园网侧地址或默认路由。

## 4. 地址规划

| 地址或范围 | 用途 |
|---|---|
| `192.168.5.1` | 企业路由器管理地址 |
| `192.168.5.2` | 交换机管理地址（可选） |
| `192.168.5.10-49` | 受管控及测试计算节点 |
| `192.168.5.11` | RTX 4070 测试节点 `epic-cluster-compute-rtx4070-01` |
| `192.168.5.50-199` | 自由实验主机 |
| `192.168.5.200-229` | 临时 DHCP 地址池 |
| `192.168.5.250` | 旧控制节点 `epic-cluster-controller-02` |
| `192.168.5.251` | 新控制节点 `epic-cluster-controller-01` |
| `192.168.5.255` | 广播地址，不分配 |

固定地址、主机名和网卡 MAC 地址最终记录在项目 inventory 中。路由器固定租约只作为辅助管理，Linux 主机自身仍保留静态配置。

## 5. 数据路径

### 集群内部通信

```text
计算节点 → 交换机 → 路由器 LAN 交换平面 → 控制节点集群网口
```

同一子网通信只经过二层交换，不经过路由器 WAN 或 NAT。

### 计算节点访问互联网

```text
计算节点
  → 默认网关 192.168.5.251
  → 控制节点 IPv4 forwarding
  → nftables masquerade
  → 控制节点校园网口
  → 校园网
```

返回流量由控制节点的连接跟踪恢复到原始计算节点地址。

### 用户访问

- 用户通过控制节点的校园网地址访问 Open OnDemand。
- 用户从外部 SSH 到计算节点时，以控制节点作为 SSH ProxyJump。
- 内部节点不向校园网直接暴露地址或端口。

## 6. 故障边界

| 故障 | 影响 |
|---|---|
| 校园网断开 | 内网 Slurm 与节点间通信继续；互联网和外部 OOD 访问中断 |
| 控制节点停止 | 内部二层通信继续；Slurm 控制、OOD、跨网 SSH 和互联网出口中断 |
| 路由器停止 | 连接在其后的交换机与控制节点断开；已配置静态地址也无法跨越物理链路 |
| 交换机管理界面不可用 | 默认二层转发正常时不影响集群 |
| DNS 不可用 | IP通信和Slurm内部固定解析继续；域名访问失败 |

## 7. 实施顺序

1. 识别控制节点校园网口和集群网口，记录接口名、MAC、地址和路由。
2. 将集群网口设置为 `192.168.5.251/24`，确保不产生第二条默认路由。
3. 配置路由器 LAN 地址、DHCP池和默认网关选项。
4. 给 RTX 4070 节点配置 `192.168.5.11/24` 和默认网关 `192.168.5.251`。
5. 先验证控制节点与4070节点的双向内网通信。
6. 在控制节点启用 IPv4 forwarding 和最小 nftables NAT/forward规则。
7. 验证IP、DNS和互联网访问，并重启两端验证配置持久化。
8. 网络验收后继续部署MUNGE和Slurm。

## 8. 验收标准

1. 控制节点只有校园网口提供默认路由。
2. 控制节点能通过 `192.168.5.11` 访问4070节点，4070能访问 `192.168.5.251`。
3. 4070节点默认网关为 `192.168.5.251`。
4. 4070能访问公网IP并解析域名。
5. 路由追踪第一跳为 `192.168.5.251`，不存在路由环路或双重NAT。
6. 校园网无法直接发起到 `192.168.5.0/24` 的连接。
7. 重启控制节点、路由器和4070后，固定地址、路由、转发和NAT仍然有效。
8. Slurm配置只引用内部固定主机名和地址。
