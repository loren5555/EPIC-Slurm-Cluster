# 📄 Slurm 批处理任务脚本编写指南

# 1. 通过Script App 提交任务

可以在主页的直接打开Script APP，设定好参数与脚本路径即可。

# 2. 通过Job Composer 提交任务
![alt text](image.png)
可以选择使用Template或自己写一份脚本。自己写脚本参考Help中的Slurm文档。下面介绍模板方法。

> 1. 在新建中选择from template
> 2. 配置右侧任务名与集群名后点击Create New Job。
> 3. 确认任务信息
> 4. 在Jobs中查看新建的任务，确认任务信息，修改脚本内容。
> 5. 点击Submit提交任务。（注意Completed可能包括执行完成与任务成功提交但是跑挂了两种情况，需要根据sh脚本输出自行判断。）

job结构：   
>```bash
>Job
>├──manifest.yml  # 定义了Job名称等元信息，通常不需要修改。
>├──script.sh  # 任务脚本，名称与manifest中定义的对应
>└──其它脚本依赖的文件。总大小不超过65kb
>```

# 3. 任务脚本说明
在提交作业时，需要提供一份 Shell 脚本。该脚本包含要运行的程序代码，并在头部通过 `#SBATCH` 指令向集群声明需要的硬件资源。

以下是模板脚本的结构解析及编写说明：

#### 1. 资源请求参数 (`#SBATCH` 指令)
脚本前几行以 `#SBATCH` 开头的注释，是 Slurm 识别资源需求的专属标识。您可以根据实际任务需求修改对应的值：

| 参数指令 | 示例值 | 含义及修改建议 |
| :--- | :--- | :--- |
| `-p` / `--partition` | `epic-cluster-compute-a100-01` | **计算分区**。当前每台物理主机对应一个同名分区。 |
| `-t` / `--time` | `1-00:00:00` | **运行时间限制**。格式为 `天-小时:分钟:秒`。请预估任务时长，超时后任务将被强制终止。 |
| `-c` / `--cpus-per-task`| `4` | **CPU 核心数**。为该任务分配的 CPU 数量。如果需要进行大量数据预处理，可适当调大。 |
| `--gres` | `gpu:2` | **GPU 资源**。格式为 `gpu:数量`。硬件型号由所选主机分区决定。 |
| `-o` / `--output` | `logs/%A-%a.out` | **标准输出日志**。保存程序执行时的 `print` 等正常输出。`%A` 会自动替换为当前任务的 ID。 |
| `-e` / `--error` | `logs/%A-%a.err` | **错误输出日志**。保存程序的报错信息，方便任务失败时排查原因。 |

> **💡 提示：** 脚本中预设了将日志保存在 `logs/` 文件夹下。请确保您的工作目录中包含此文件夹，或由系统平台自动处理。

#### 2. 脚本安全与运行环境设定
在资源声明之后，脚本包含了一些环境设定代码：

* **防御性执行 (`set -exuo pipefail`)**：
  这是一项严格的 Bash 运行机制。
  * **遇到错误即停止**：一旦某行代码报错，脚本会立即停止，防止错误蔓延并浪费计算时长。
  * **日志打印执行过程**：会将执行的每一行指令打印到 `.err` 日志中，极大方便了代码调试。
  * *(如果您觉得日志中包含太多执行过程的信息，可以将其修改为 `set -euo pipefail` 关闭过程打印)*。

* **元数据打印**：
  脚本会自动获取并打印当前的工作目录 (`pwd`)、主机名 (`hostname`) 以及系统分配的任务 ID (`SLURM_JOB_ID`)，方便后期追溯任务的运行位置。

#### 3. 编写核心任务代码 (Main Script)
脚本最后的 `# Main Script` 部分是您真正需要执行的任务代码。

模板中默认提供了一个示例Python脚本作为占位符。**在实际使用时，请将其删除并替换为您自己的执行逻辑。**

## **常见的脚本示例（运行深度学习训练）：**

```bash
#!/usr/bin/env bash

# ==========================================
# 1. Slurm 资源申请指令 (#SBATCH)
# ==========================================
#SBATCH -p epic-cluster-compute-a100-01  # 提交到 A100 主机对应的分区
#SBATCH -t 1-00:00:00                    # 最大运行时间限制 (天-小时:分钟:秒)
#SBATCH -c 4                             # 申请的 CPU 核心数
#SBATCH --gres=gpu:2                     # 从所选主机申请 2 张 GPU
#SBATCH -o logs/%A-%a.out                # 标准输出日志文件 (%A, %a 会被自动替换为 Job ID 与 运行序号)
#SBATCH -e logs/%A-%a.err                # 错误输出日志文件

# ==========================================
# 2. 环境设定与调试保护
# ==========================================
# 开启 Bash 严格模式：
# -e: 遇到任何报错立即停止
# -x: 将执行的每一行命令打印到错误日志中，方便排查问题
# -u: 使用未定义变量时报错
# -o pipefail: 管道命令中任何环节报错即整体停止
set -exuo pipefail

# 自动创建 logs 文件夹以防因目录不存在导致任务直接失败
mkdir -p logs

# 打印基础元信息，方便后期追溯和日志归档
echo "=========================================================="
echo "Starting Job ID: ${SLURM_JOB_ID}"
echo "Running on node: $(hostname)"
echo "Current directory: $(pwd)"
echo "=========================================================="

# ==========================================
# 3. 核心任务区 (Main Script)
# ==========================================
echo ">>> 第1步: 切换至工作路径..."
# 切换至要执行的脚本期望的工作路径
cd /path/to/you/workspace

echo ">>> 第2步: 激活运行环境..."
# 请将下方路径替换为您实际的 conda/venv 激活脚本路径和环境名称
# 例如: source ~/miniconda3/bin/activate my_pytorch_env
source /path/to/your/miniconda3/bin/activate your_env_name

echo ">>> 第3步: 开始执行训练代码..."
# 运行您的主程序，并传入所需参数
python train.py \
    --batch_size 128 \
    --epochs 100 \
    --learning_rate 0.001 \
    --output_dir ./checkpoints

echo "=========================================================="
echo ">>> 任务全部运行完毕！"
echo "=========================================================="
```
