# 文档维护

文档按用途分层：

- 用户文档回答“怎样完成一次任务”；
- 管理员文档回答“怎样部署和维护服务”；
- 开发者文档回答“怎样修改仓库并验证变更”。
- 故障手册保存与当前流程匹配的错误处理；
- `Other` 保存一次部署、手工操作和历史记录索引。

不要把实现计划、历史讨论或设计推导直接放进用户页面。过程记录和架构决策保存在
`docs/superpowers/plans/`、`docs/superpowers/specs/`，并明确它不是当前操作手册。重组时
可以归纳或移动，但不要删除这些原始记录；用 `Other` 说明内容的现行去向。

修改文档时：

- 使用仓库相对路径链接；
- 新增页面后从 `docs/index.md` 或对应分类入口可达；
- 命令附简短用途说明，避免只列命令不解释结果；
- 使用当前完整主机名分区和当前资源策略；
- 不在公开文档中写密码、密钥、Vault 内容或内部临时状态。

提交前运行与变更相关的行为测试、身份清单验证和 `git diff --check`。不要用测试重复
证明真实入口已经证明的前提，例如 IAPP 已成功启动后再断言 APP 目录和每段配置文本
存在。部署可用性由一次真实作业、IAPP 或页面访问人工验收。
