# 文档维护

文档分三层：

- 用户文档回答“怎样完成一次任务”；
- 管理员文档回答“怎样部署和维护服务”；
- 开发者文档回答“怎样修改仓库并验证变更”。

不要把实现计划、历史讨论或设计推导直接放进用户页面。当前仍有效的架构决策可以保存在 `docs/superpowers/specs/`，文件顶部应说明它是决策记录，不是操作手册。

修改文档时：

- 使用仓库相对路径链接；
- 新增页面后从 `docs/index.md` 或对应分类入口可达；
- 命令附简短用途说明，避免只列命令不解释结果；
- 使用当前完整主机名分区和当前资源策略；
- 不在公开文档中写密码、密钥、Vault 内容或内部临时状态。

提交前运行全量测试、身份清单验证、链接搜索和 `git diff --check`。
